결론 먼저 (TL;DR)

스타일라이즈 애니풍 + PC/콘솔 풀퀄이라면, 순수 사실주의 레이마칭(Nubis식)을 그대로 쓰는 건 과한 비용이야. 핵심은 "볼륨의 실루엣/시차감은 살리되, 라이팅은 셀/램프로 단순화"하는 하이브리드다.

  • ★ 1순위 — UE5 Volumetric Cloud 컴포넌트 + 커스텀 머티리얼. 라이트 적분 단계를 표준 Beer/HG 대신 램프 LUT·포스터라이즈로 갈아끼워 셀 구름화. 풀퀄 환경에서 실루엣과 라이트 시프트를 공짜로 얻으면서 아트 방향만 비튼다.
  • ★ 2순위 — 지브리/카드 룩이 목표면 스카이돔/빌보드 + 셀 그라데이션 램프 셰이더. 가장 싸고 가장 "그림" 같다. 시차감·통과비행은 포기.
  • ★ 보조 — Ultra Dynamic Sky를 베이스로 깔고 그 위 머티리얼만 스타일라이즈하면 시간대/날씨 시스템을 통째로 재활용 가능.

근거: Nubis 자체가 PS4에서 ~2ms까지 최적화된 사례 검증됨이고, UE5 Volumetric Cloud 머티리얼은 2개 위상함수 블렌드 + 채널별 노이즈 패킹 구조라 셀화 진입점이 명확함 검증됨.

1. 진짜 볼류메트릭 레이마칭 클라우드

3D 노이즈로 밀도장을 만들고, 카메라 레이를 따라 행진(raymarch)하며 밀도 적분 + 라이트 방향 샘플로 음영을 누적하는 방식. 업계 레퍼런스의 사실상 표준은 Guerrilla의 Nubis(Decima 엔진, Horizon 시리즈).

Nubis 핵심 기법 검증됨

  • Perlin-Worley 합성 노이즈 — Perlin과 반전 Worley를 곱(multiply)이 아니라 remap으로 합성해 저밀도 영역에 둥근 구름 베이스를 부여. 곱하면 코어 밀도가 날아가므로 remap을 씀. 
    perlin-worley = remap(perlin, 1.0 - worley, 1.0, 0.0, 1.0)
  • 라이팅 = Beer-Lambert + Henyey-Greenstein — 감쇠는 Beer-Lambert, 전방산란 방향성은 HG. Nubis는 HG 로브 2개를 max()로 결합하고 Beer 함수 2개를 써서 다중 내부산란을 근사.
  • 적응형 레이마칭 — 시선 방향에 따라 54~96 step. 저주파 노이즈에선 크고 싼 스텝, 밀도가 잡히면 짧고 정밀한 풀 샘플. 라이팅은 라이트 정렬 콘에서 5개 밀도 샘플, 샘플마다 LOD를 낮춤.

성능 — "비싸다"는 편견을 깨는 최적화 단계 검증됨

최적화 단계 (Standard PS4)렌더 시간
미최적화 셰이더22 ms
+ 적응형 스텝 / LODing8.1 ms
+ 구름 내부에서만 라이트 샘플3.34 ms
+ 오클루전 인지 레이마칭 시작점1.2 ms
+ 리프로젝션(temporal) → 최종 프레임 예산~2 ms

즉 콘솔 풀퀄 예산(~2ms)에서 실시간 볼류메트릭은 충분히 viable. 2015 프로토타입이 이미 PS4에서 다양한 구름·조명 조건을 2ms 미만에 렌더 검증됨. 2023년엔 2.5D→복셀 기반으로 전환, 압축 SDF로 레이마칭 가속 검증됨.

스타일라이즈하게 비트는 법 도메인 지식

  • 라이트 적분을 램프 LUT로 치환 — Beer-Lambert의 연속 감쇠값을 1D 램프 텍스처로 인덱싱해 2~3단계로 양자화. 곧바로 셀 구름 음영이 나온다.
  • Posterize(계단화) — 최종 밀도/광량을 floor(x * N)/N로 밴딩. 애니풍 "면 분할" 룩.
  • 다크 엣지 / 인너 글로우 — Nubis의 저비용 근사 기법을 과장해 테두리 진하게, 내부 밝게 → 일러스트 구름 느낌.
  • 실루엣 단순화 — 디테일 노이즈 기여도를 낮추고 베이스 형태 위주로. 고주파를 죽일수록 "그림" 같아진다.

2. 카드 / 빌보드 스타일라이즈 클라우드

구름을 3D 부피가 아니라 평면(스카이돔 텍스처, 빌보드 스프라이트, 패럴랙스 레이어)으로 그리고, 셀 그림자·램프로 칠하는 방식. 지브리·원신·붕괴 등 서브컬쳐 정석 룩.

서브컬쳐 게임 셰이더 특징 출처확보·미검증 도메인 지식

Genshin Impact 계열

하늘은 그라데이션 램프 + 큰 면 단위 셀 구름. 캐릭터 셰이더의 램프/림 기법이 환경에도 일관 적용. 셰이더 재현 분석이 다수 공개됨(80.lv, bjayers 블로그).

Ghibli / 손그림 룩

붓터치 텍스처 + 단순 2~3톤 음영. UE5 NPR 셰이더로 재현 사례 존재(80.lv Ghibli-style shader). 디테일보다 색·실루엣·면 분할.

Honkai 계열

채도 높은 색 그레이딩 + 부드러운 셀 경계(스무스 스텝). 시간대별 색 팔레트 전환을 적극 활용.

장단점 정리

항목평가
비용최저. 텍스처 샘플 + 머티리얼 수식 몇 개.
룩"그림" 재현력 최강. 아트 디렉션 100% 통제.

3. 하이브리드 (Ultra Dynamic Sky류 + RGBA 패킹)

카드의 저비용과 볼류메트릭의 입체감 사이 절충. UDS 같은 패키지는 여러 구름 모드(볼류메트릭/스태틱/2D 다이내믹/복셀)를 한 시스템에 묶어 성능·룩 티어를 제공한다고 알려짐 출처확보·미검증.

RGBA 채널 패킹 패턴 검증됨(원리)

볼류메트릭/하이브리드 공통으로 노이즈를 채널별로 패킹해 한 번의 샘플로 여러 정보를 읽는다. UE5 Volumetric Cloud 머티리얼도 채널별 노이즈 패킹 + 채널별 Noise 컨트롤 구조 출처확보·미검증. Nubis의 전형적 2D 클라우드맵 패킹은:

채널역할 (전형 패턴)
RPerlin 노이즈 — 연결된 구름 덩어리
GPerlin-Worley — 고립된 섬 형태
B저주파 노이즈 — 구름 타입(0 stratus / 0.5 stratocumulus / 1 cumulus)
A커버리지 / 높이 / 밀도 마스크 (구현별)

위 채널 의미는 Nubis 발표 자료 기반 일반 패턴 출처확보·미검증. 실제 패킹은 프로젝트 요구에 맞춰 의미를 먼저 정의하고 임포트해야 함(프로젝트 룰과 일치).

UDS 베이스 + 스타일라이즈 전략 도메인 지식

  • UDS의 시간대/날씨/문라이트 시스템은 그대로 두고 구름 머티리얼만 오버라이드해 램프·포스터라이즈 적용.
  • 2D 다이내믹 모드는 스카이스피어 머티리얼 효과(가짜 시차) → 가장 싸게 움직이는 구름.
  • 볼류메트릭 모드는 풀퀄 컷신용, 2D/스태틱은 게임플레이용으로 LOD 스위칭.

4. 표면 셰이딩 기법 (룩 레이어)

형상 기법 위에 얹는 마감. 셀/램프, 림라이트, 컬러그레이딩, 포스터라이즈, 노멀 기반 음영. 독립 구름 기법이 아니라 ①②③ 공통 도구.

셀 / 그라데이션 램프

연속 N·L(또는 밀도/광량)을 1D 램프 텍스처로 인덱싱해 단계화. 상용 셀 셰이더(Flatkit, Quibli)는 None/Single/Steps/Curve 같은 모드와 R8 램프 텍스처를 사용한다고 알려짐 출처확보·미검증.

림라이트

Fresnel(1 - N·V)로 테두리 발광. 구름 실루엣을 광원 방향으로 밝혀 "빛 머금은 가장자리". 역광 구름의 핵심.

포스터라이즈

floor(x*N)/N로 색/광량 밴딩. 애니 면분할. 램프와 병용하면 깔끔한 계단 음영.

컬러 그레이딩

시간대별 팔레트(아침/노을/밤)를 램프 색으로 직접 지정. 사실 라이팅 대신 아트가 고른 색으로 분위기 제어.

노멀 기반 음영

카드 구름엔 가짜 노멀맵으로 면 음영을, 볼류메트릭엔 그래디언트 기반 의사 노멀로 셀 경계 생성.

5. Unreal Engine 5 구현 접근법

A. Volumetric Cloud 컴포넌트 + 셀화 머티리얼 (추천) 검증됨(구조)

UE5의 Volumetric Cloud 머티리얼은 위상함수 2개를 Phase Blend로 블렌드(0=Phase A, 1=Phase B, 방향성 파라미터 -1~1)하고, multiscatter(intensity/occlusion/eccentricity, 0~1)와 채널별 노이즈 컨트롤을 노출한다 검증됨 / 일부 미검증.

  • 네이티브 노드로 의미(좌표, 노이즈 샘플, 커버리지, 파라미터)를 유지하고, 라이트 응답 곡선만 램프 LUT/Posterize로 교체 → 셀 구름.
  • 어려운 수식 섬(노이즈 해시, remap, HG)은 작은 Custom HLSL 노드로 격리(프로젝트의 하이브리드 머티리얼 원칙과 일치).
  • compile_error_count=0 확인 후 저장, Custom 노드 수·연결 입력 검증.

B. Custom HLSL 풀 레이마처

네이티브로 부족할 때 SceneCapture/포스트프로세스에 레이마칭 HLSL을 직접 작성. 모바일 대응 사례(저해상 렌더타깃 320×180 업스케일, 64 density/2 light step로 구형 모바일 60fps)도 보고됨 출처확보·미검증. PC/콘솔 풀퀄에선 굳이 모바일 트릭 불필요.

C. 카드 / 스카이돔 머티리얼

Unlit/Default 머티리얼 + 램프 텍스처 + 패럴랙스 UV. 가장 단순하고 룩 통제 최강. 지브리 NPR 셰이더가 이 경로.

// 셀 구름화 핵심 의사코드 (라이트 적분 치환)
float density = SampleCloudDensity(p);          // 네이티브 노이즈 패킹 샘플
float light   = BeerLambert(opticalDepth);      // 표준 감쇠
// --- 스타일라이즈 치환 ---
float celLit  = Texture2DSample(RampLUT, light).r;   // 1D 램프로 양자화
celLit        = floor(celLit * Steps) / Steps;       // 포스터라이즈
float rim     = pow(1.0 - saturate(NdotV), RimPow);  // 림라이트
float3 col    = lerp(ShadowColor, LitColor, celLit) + rim * RimColor;

맵 전환은 프로젝트 룰대로 Python load_map 금지, 네이티브 open_editor_level/safe_new_preview_map 사용. 머티리얼 작업은 MCP로 노드 나열→컴파일 검증→저장 순.

6. Cubeless 추천 레시피

단계별 권장 경로

  1. 룩 프로토타입 — 스카이돔 카드 구름 + 램프/포스터라이즈/림으로 목표 룩을 먼저 확정(가장 싸게 아트 디렉션 락).
  2. 입체감 필요 판단 — 카메라가 구름에 가까워지거나 통과/시차가 필요하면 UE5 Volumetric Cloud로 승격.
  3. 셀화 머티리얼 — Volumetric Cloud 머티리얼의 Phase/멀티스캐터를 단순화하고 라이트 응답을 램프 LUT로 교체. 1번에서 확정한 팔레트 재사용.
  4. 성능 패스 — 적응형 스텝/리프로젝션로 콘솔 ~2ms 타깃. 게임플레이는 LOD 다운(2D), 컷신은 풀 볼류메트릭.
  5. 날씨/시간대 — 필요하면 UDS를 베이스로 깔고 구름 머티리얼만 오버라이드해 시스템 재활용.

요약: "카드로 룩 잡고 → 필요한 곳만 볼류메트릭으로, 라이팅은 끝까지 램프/포스터라이즈로 셀화". 이게 서브컬쳐 풀퀄의 현실적 황금경로야.
