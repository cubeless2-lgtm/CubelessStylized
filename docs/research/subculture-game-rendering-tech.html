한 줄 요약

"PBR 기반 스타일라이즈드 파이프라인 위에, 캐릭터만 별도 NPR/셀 셰이딩 레이어를 얹는다" — 이게 업계 표준 구조다. 원신이 GDC 2021에서 공개한 "캐릭터와 씬을 서로 다른 두 렌더 파이프라인으로 처리"가 대표 레퍼런스.

1렌더링·그래픽 기술

1-1. 전체 구조 (원신 / GDC 2021) 검증 3-0

  • 전통적 셀 셰이딩이 아니라 PBR 기반. 단 완전한 에너지 보존은 안 하고, 머티리얼별 라이팅 모델을 아트 요구에 맞게 변형.
  • 캐릭터는 이 위에 NPR 레이어(커스텀 셀 라이팅 + SDF 페이스 섀도우 + 램프 음영 + 외곽선)를 얹음.
  • GDC 2021 슬라이드 키워드: Different render pipelines for characters and scenes, Face dynamic lightmap, Artificially controlled shadow effect, Real-time lit environment.
출처: miHoYo 기술디렉터 Zhenzhong Yi "From Mobile to Console" Unity 강연 · GDC 2021 'Genshin Impact: Crafting an Anime-Style Open World' (Haoyu Cai)

1-2. ★ SDF 페이스 섀도우 — 가장 핵심 기법 검증 3-0

얼굴은 노멀 기반 N·L을 버리는 게 포인트. 노멀로 하면 코·눈두덩 음영이 지저분해지기 때문.

런타임 로직:

FdotL = dot(faceForward.xz, lightDir.xz)   // xz 평면(수평) 내적
정규화: (-FdotL + 1) / 2  →  [0,1]
비교:   step((-FdotL + 1) / 2, FaceShadowMap)   // 베이크 텍스처와 임계값 비교
우측 광원일 때: UV 뒤집음 (1 - V)               // 좌우 대칭 처리
  • 한쪽 얼굴의 0~180도 광원 각도 그림자 분포를 1장에 베이크. 광원이 돌면 손그림 그림자 마스크가 자동으로 따라 변함.
  • 노멀 편집 없이 부드러운 감쇠를 얻고, 그림자 경계는 램프 텍스처 컬러 블렌딩으로 스타일라이즈.

소스 제작 워크플로우 (AnimeShadingPlus 기준):

  1. 0~180도를 9단계로 쪼개 한쪽 얼굴에 9장 손그림 (9는 표준, 최소 2장↑, 많을수록 디테일)
  2. Tools/ASP > SDFGenerator로 각 장을 개별 SDF 변환 → Create SDFs & Merge로 통합 1장
  3. 머티리얼 Face Shadow Map 슬롯에 할당
ℹ
선택 이유 — 프록시 노멀/DCC 수동 노멀 수정 대비 아티스트 제어성 높고 작업시간 적음. 단 이건 저자 의견이고 런타임 비용이 아니라 작업 효율 기준 (검증 2-1).
출처: AnimeShadingPlus 매뉴얼 · NoiRC256/URPSimpleGenshinShaders · noirccc.net · PrimoToon

1-5. 셀프 섀도우 처리 검증 3-0

셀 셰이딩 특유의 지저분한 셀프 섀도잉을 막으려고 캐릭터를 별도 섀도우 맵에 따로 렌더링(URP 기본 섀도우를 넘는 별도 렌더 패스). 얼굴 그림자 제어는 바디와 분리(Face Mode).

1-4. 램프 텍스처 음영 — 임포트 세팅 함정 검증 3-0

⚠
실무에서 제일 자주 틀리는 부분 — 박아둘 것
  • 모든 램프 텍스처: Wrap Mode = Clamp (Repeat 쓰면 그림자 타일링 아티팩트)
  • Specular 램프: sRGB 해제 (안 하면 컬러 왜곡)
  • 페이스 섀도우 / 라이트맵 / 노멀맵: sRGB 해제 (색이 아니라 데이터니까)
  • PrimoToon 재현 시: Color Space를 Linear로 강제 (Gamma면 결과 틀어짐)

톤은 2~3단계 설정형 램프(임계값·smoothness 조절) + 그라데이션 램프 텍스처로 구동.

출처: Delt06/urp-toon-shader · PrimoToon · Roystan 툰 튜토리얼

2캐릭터·리깅·애니메이션

2-1. 스프링본 흔들림 물리 (머리카락·옷·꼬리·장식) 검증 3-0

VRM SpringBone(UniVRM / VRMC_springBone)이 표준 참조. Verlet 적분 기반 — 속도를 저장 안 하고 prevTail/currentTail 위치만 추적:

nextTail = currentTail + inertia + stiffness + external
  inertia   = (currentTail - prevTail) * (1.0 - dragForce)   // 관성
  stiffness = rest 방향 복원력 (stiffnessForce)               // 강성
  external  = gravityDir * gravityPower                       // 중력/외력
→ 본 rest 길이로 length-constrain (길이 구속)
→ sphere/capsule 콜라이더 충돌 처리

조인트별 파라미터: stiffnessForce(복원력), dragForce(0~1 감쇠), gravityPower, gravityDir(기본 (0,-1,0)), hitRadius(충돌 반경).

⚠
주의 — 이건 VTuber/아바타용 범용 OSS 표준이다. Verlet + 관성/강성/중력 3성분은 업계 보편 패턴이라 실무 참조론 유효하지만, 원신/블루아카이브가 정확히 이 구현을 쓴다는 직접 증거는 없다. 개념적 표준으로 받아들일 것.
출처: vrm-c/vrm-specification (VRMC_springBone-1.0) · UniVRM VRMSpringBone.cs · vrm.dev · DeepWiki

3아트 파이프라인·제작

3-1. 블루 아카이브 3D 배경 — 생산성 사례 (NDC 2025) 검증 3-0

  • "2.5명"(2명 시작 → 출시 시 3명)으로 약 2년 만에 배경 완성. (발표자: 3D 배경팀장 최진우)
  • Substance Designer 노드 기반 재사용 텍스처 시스템이 핵심. 예: 적합한 이미지를 넣으면 아스팔트 음각 패턴이 자동 생성.
  • 전면 적용이 아니라 전략적으로 적용해 생산성↑.
출처: thisisgame · gamevu 등 6개 매체 교차검증 (인원수만 출처 간 2~3명 미세 차이)
